How it works

A chat on one side, your tools on the other

Pi Bot is a small gateway between your chat app, a language model and the tools you choose to connect. Nothing to open in a browser: setup happens in a terminal, and everything else happens in the chat.

  1. You send a message

    Text, a photo or a voice note, on Telegram or on WhatsApp. One gateway per install, chosen during setup.

  2. Only allowed senders get in

    Telegram accepts the numeric user ids you list. WhatsApp accepts the owner's number, any extra numbers you add and your own “message yourself” chat. Everyone else is ignored.

  3. Your model answers

    The text model you picked runs the turn on the pi.dev harness. An optional image model reads photos and an audio model transcribes voice notes.

  4. Tools do the work

    Mail, calendar, search and more come from MCP servers you connect. Calls that need approval wait for your OK in the chat.

One container, one volume. Settings, credentials and conversations live in SQLite files on the Docker volume mounted at /app/data; the image itself is read-only. The assistant has no shell, file system or browser of its own: anything it does outside the chat goes through the tools you connect.

Setup

Ready in five steps, all in the terminal

npm run setup is an interactive menu that edits one section at a time. Enter keeps a saved value, secrets stay hidden, and each section is written to the volume when you choose Save and back.

  1. Open the setup menu

    With the container up, run npm run setup inside it. A fresh container stays up and healthy while it waits, and no environment variable is required to boot.

    The main menu lists every section: gateway, text model, image model, audio model and MCP platform.

  2. Choose a gateway

    Under Setup gateway, pick Telegram or WhatsApp. There is one gateway per install: saving one turns the other off.

    • Telegram asks for the bot token (hidden as you type) and the numeric user ids allowed to talk to the bot.
    • WhatsApp continues in the next step.

  3. Link WhatsApp (if you chose it)

    Enter the owner's number with country code; extra allowed numbers are optional. Then pair the phone in one of two ways:

    • Pair with QR — scan it in WhatsApp under Linked devices.
    • Pair with phone code — type the code the terminal prints.

    The session is stored on the volume, so it survives restarts.

  4. Pick your models

    Text model takes any official pi-ai provider (Anthropic, OpenAI, Google, Groq, OpenRouter, xAI, DeepSeek and others) with an API key, or ChatGPT Plus/Pro sign-in with no API key at all.

    Image model and Audio model are optional: they let the bot read photos and transcribe voice notes.

  5. Connect tools and go live

    Under MCP platform, choose Composio, Executor, Upsy, a self-hosted gateway, Executor plus Composio, or none.

    Then pick Save and restart gateway: the running bot reloads from the volume — no image rebuild needed. Say hi in the chat and send /status to check the model, MCPs and version.

Features

What Pi Bot does today

Everything here is described in the README and implemented in the code.

  • Telegram or WhatsApp

    Telegram via the Bot API, or WhatsApp linked as a device with a QR or pairing code. One gateway per install, with an allow list of who may talk to it.

  • Your model, your choice

    Any official pi-ai provider with an API key, or ChatGPT Plus/Pro sign-in without one. Switch model and reasoning effort from the chat with /model and /thinking.

  • Photos and voice notes

    Send a picture or speak instead of typing. A vision-capable model reads photos and an audio model transcribes voice notes. Replies are always text.

  • Scheduled tasks

    Ask in the chat for a one-off reminder or a recurring job (five-field cron), each with its own timezone. A run stays silent unless it has something to tell you. Manage them with /crons.

  • Tools over MCP

    Plug in Composio, Executor, Upsy (OAuth, no API key) or any self-hosted MCP gateway. Add more servers — search, mail, GitHub — with a small JSON list.

  • Approvals before actions

    When Executor pauses a call for approval, the bot relays it to you as a card. A write whose result is unknown is never resent; you decide with /resume.

  • Separate conversations

    /new starts fresh while the old conversation stays on the volume. On Telegram, each forum topic has its own history, model and effort. /compact condenses a long one.

  • Operator skills

    Drop SKILL.md folders on the volume and list them in config.yaml. The model can read them on every reply, scheduled runs included.

  • Optional code tasks

    sandbox_code_task runs long coding jobs on an Instabox machine. It is off until you configure it, the repository allow list starts empty, and pushes or pull requests wait for your approval.

  • Self-hosted and locked down

    Docker Compose with a read-only image, all capabilities dropped and a health check. Configured secrets and bearer tokens are redacted from logs.

Quick start

From zero to a working bot

You need Docker with Compose and either a Telegram bot token or a WhatsApp account to link. An API key for your model is optional if you sign in with ChatGPT.

Shell 
# 1. Get the code and start the container
$ git clone https://github.com/forge-z/pi-bot.git
$ cd pi-bot
$ cp .env.example .env
$ docker compose up -d --build

# 2. Configure gateway, models and MCP (interactive)
$ docker compose exec pi-bot npm run setup

# 3. Check the saved state at any time
$ docker compose exec pi-bot npm run setup -- --list

The README uses the equivalent docker exec -it <container> npm run setup. Every variable in .env is an optional override; leave it empty and setup stores everything on the volume. If the gateway is already running when you pair WhatsApp, read the QR from docker compose logs instead.

On Telegram these appear in the bot menu; on WhatsApp, type them as text.

FAQ

Frequently asked questions

Can one install use Telegram and WhatsApp at the same time?

No. Each install has one gateway. Saving WhatsApp in setup turns Telegram off, and the other way around. An install that never chooses stays on Telegram.

Is the WhatsApp connection official?

No. The WhatsApp gateway uses Baileys, which speaks the unofficial WhatsApp Web protocol and can lead to account restrictions. Keep that in mind when choosing which number to link.

Do I need an API key for the model?

Not necessarily. Setup offers ChatGPT Plus/Pro sign-in (OAuth) with no API key. For any other official pi-ai provider — Anthropic, OpenAI, Google, OpenRouter and more — you enter that provider's key in setup.

Where is my data stored?

On the Docker volume pi_bot_data, mounted at /app/data: settings, credentials, conversations and the WhatsApp session. The image is read-only. Your history is only as private as that volume and the host it runs on.

Can it talk back with voice?

No. It understands voice notes when an audio model is configured, but it always replies in text. A tool can produce an audio file, but a voice bubble is not implemented.

Does it work in groups?

On WhatsApp, groups, broadcasts and newsletters are ignored. On Telegram, group and topic ids can be allowed with the TELEGRAM_ALLOWED_CHATS environment variable, and each forum topic keeps its own history, model and effort.

How do I give it new abilities?

Connect an MCP server instead of changing the bot. Choose a platform in setup, or list extra servers in a JSON file named by MCP_CONFIG_FILE. Keys stay in environment variables, never in the file. The README suggests services for mail, search, scraping, calendar and more.

How do scheduled tasks reach me?

Just ask in the chat — for example, “remind me every Monday at 9:00 to review my open tasks”. The schedule stays in that chat, with its own timezone. When it runs, it only sends you a message if it decides there is something to report.

Is it production-ready?

Pi Bot is in beta: usable day to day, but configuration and commands may still change between releases. Back up the volume before upgrading.
